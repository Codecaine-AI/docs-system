# Docs Publish Compatibility Package

This local proof reuses DocBlockRenderer to render an explicitly selected public collection as HTML. Optional search runs in the browser. Canvas and Sequence render through their own static SVG renderers during the build. Fitted diagram images appear directly, even without JavaScript. Clicking an image loads the existing Docs workbench Canvas or Sequence fullscreen component with validated static data. Canvas uses its native pan/zoom stage; Sequence retains its existing Fit/zoom toolbar. No download UI is added; the preview remains a normal browser image.

From the docs-system root, run `bun packages/docs-publish/build.ts`, then run `npm pack` in this package. The archive includes the Node publisher, browser assets, styles, and source provenance. Consumers need Node, not this checkout or Bun. The version in package.json identifies a local compatibility artifact, not a registry release.

Use `publishCollection({root, posts, basePath})`. Each allowlisted post has `path`, `slug`, `description`, `date` in YYYY-MM-DD form, `tags`, and optional `draft`. Drafts are excluded before reading content. Results contain HTML posts, public search entries, and referenced asset bytes. Each post's `viewers` flag is true when it has a diagram or an expandable image; load `browser/viewers.js` on those pages so clicks open the full-screen viewer. Hosts own page shells, feeds, sitemaps, canonical origins, and UI placement.

Published articles look like the Docs workbench read view under the repo Default theme (`themes/default`), in light and dark mode. `dist/styles/docs.css` ships the workbench token layer (palette and semantic tokens), the shared read-surface rules, the Typography plugin and a Tailwind preflight scoped to `.docs-markdown`. It ships no global element rules: outside the article only `:root` token declarations apply, and unlayered host CSS still wins. Call `docsThemeHead()` at build time. It returns `{htmlAttributes, css}`: put the attributes on `<html>` (`data-code-panels="dark"` renders code blocks as dark panels) and the CSS in a `<style>` after `docs.css`. The CSS is the theme's style-rail variables and override rules, read from `themes/default` when this package is built. Dark mode follows `data-theme="dark"` or a `.dark` class on an ancestor, which the host sets.

Published text paints in the faces its layout is measured with: Inter for prose and diagrams, IBM Plex Mono for code (`@codecaine-ai/text-measure`). `docs.css` loads them itself: it imports `@codecaine-ai/design-system/fonts.css`, and the build writes the woff2 files next to it in `dist/styles/` (relative URLs, so serve that folder as a whole). `dist/fonts.css` (`@codecaine-ai/docs-publish/fonts.css`) declares the same faces for pages without `docs.css`, and `dist/fonts/` holds the woff2 files, the TTFs and the OFL licenses. The Node publisher (`dist/node/publish.js`) loads HarfBuzz and the TTFs when it is imported, so canvas and sequence text is laid out with exact widths. Each diagram SVG embeds the faces it paints as data URLs, because an `<img>` SVG cannot load the page's fonts. `viewers.js` and the editor load the faces in the browser, and open diagrams lay out again when they arrive.

Search matches normalized words, prefixes and one-character spelling errors, weighted toward titles and tags. Common query filler is ignored. It does not infer concepts or synonyms. Call `search(entries, query, tag)` or load `browser/search-widget.js` on an element with `data-docs-search`, `data-index`, a search input, tag select, `[data-results]`, and `[role=status]`. No viewer must show the widget.

Only referenced, collection-confined files are copied. Studio-only diagrams fail the build. No local API URLs are embedded. The initial release needs clean tagged dependencies and a broader component compatibility pass; this proof does not establish a general Codecaine release policy.

Bundled videos use local `src` assets copied into the static output. The host must serve video MIME types and support byte ranges for seeking. The shared `html` block renders self-contained HTML/CSS in a sandboxed iframe; scripts require an explicit `allowScripts` setting. Code syntax colors and list markers ship in the shared component stylesheet and work without client-side highlighting.

Image-only grids use the native `image-grid` block. Set `images` to an ordered array of `{src, heading?, alt?, caption?}` and `columns` to `auto` or 1 to 4. Rows grow with the image count; narrow containers reduce columns. All image assets are bundled, and headings, captions, and alt text enter search. The shared CSS preserves image proportions and works without article JavaScript. The Docs editor supplies controls for the same stored fields.

Local draft editing uses `@codecaine-ai/docs-publish/editor` (`dist/browser/editor.js`) with `docs.css` plus `@codecaine-ai/docs-publish/editor.css`. `mountDraftEditor(container, {api, path, projectId?, onStatus?})` loads `${api}/bundle`, replaces the container's children with the Docs editor in auto-save mode, and resolves to `{reload, destroy}`. `api` is a same-origin proxy of one project's Docs `/api`; saves use its hash precondition and draft locks. `reload()` reseeds only a clean editor whose file hash changed. Editor CSS is scoped to `.docs-draft-editor` and ships no preflight. Deployed pages never load this entry.
